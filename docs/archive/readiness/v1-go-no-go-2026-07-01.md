(`docs/measurement/ec2-2026-06-30/`, m6id.4xlarge @ `ce7d719`) and a multi-machine horizontal-scale run

availability, and long-run stability are measured GREEN with honest sub-headline numbers; horizontal write
scaling is PROVEN near-linear; the single-node write envelope is characterized and root-caused. What remains
open is precisely bounded below.

| Claim | Measured | Verdict |
|---|---|---|

### 3.2 The one horizontal-scale operability follow-up (leadership balancing)

Multi-Raft leadership is **NOT auto-balanced** — and the horizontal 2.45× **requires** exactly one
group-leader per box (1-1-1). Today that is **operator-achieved** by fresh-boot-until-balanced (~4–20 boots:
a fresh simultaneous boot lands 1-1-1 only **~1 in 20**, because whichever node is ready a beat sooner
"sweeps" and wins *all* its groups) and is a **stable fixed point at rest** — but **not automatically
maintained**. `RaftNode.transferLeadership` (Raft TimeoutNow) exists in core but is **not exposed on any
admin HTTP route** and **not invoked on shutdown**, so N groups can pile leaders onto one node and forfeit
the horizontal benefit until a restart. (The aggregate is robust to *modest* imbalance — a 2-1-0 placement
still sustained 1,628/s — but a fully-swept placement is not.) This is a **genuine v1 operability gap that
gates the horizontal-scale claim in practice.** Follow-up (one item, three options): expose
`transferLeadership` via an admin endpoint, and/or a lightweight balancer, and/or transfer-on-graceful-
shutdown. `ec2-horizontal-2026-07-01/05-leadership-placement.md`

### 3.3 Bottom line

The empirical foundation **supports**: durability, availability, and long-run stability **measured GREEN**;
a **characterized** single-node write envelope (~800 w/s, churn-bound, admission-shed-stable); and
horizontal write scaling **PROVEN near-linear** (2.45×/3-machine, a conservative floor). It does **not** yet
support: an **automatically-maintained** horizontal deployment (leadership balancing is manual — the one
operability gap), a **literal sustained-10k/s or 100k-burst** number, a **full 24 h/72 h soak**, or any
**cross-region/WAN** claim (out of v1 scope). **Ship v1 on the measured envelope with those four edges
stated explicitly.**

## 4. The v1 security-posture line

**The honest lead.** Configd v1 has a real, code-wired security model — not an interface-only sketch. It
ships mutual-TLS + bearer-token authentication, an in-core RBAC authorization foundation (scope-through-API,
the `{READ, LIST, WRITE, WATCH, ADMIN}` capability vocabulary, union-of-ancestors grants with absolute
deny-precedence and default-deny, roles, and policy-as-config under `_acl/`), a whole-target watch-
authorization gate, unconditional rate limiting, at-rest **integrity** (HMAC-SHA-256), config signing, and a
fail-closed signing-key-co-location guard. The mechanisms are wired into the live request path (the
historical "interface-only" caveat is stale). v1 makes **one deliberate posture choice: it is
secure-by-config, not secure-by-default.** Except for rate limiting, every control is off until an operator
turns it on (each emits a loud startup warning when off). There is **one registered gap that is not a
posture choice: config data is not encrypted at rest** (integrity ≠ confidentiality).

**What is built and wired:**

| Control | Status | Note |
|---|---|---|
| Authentication — mTLS (cert-DN) + bearer token | Wired, **OFF by default** | Bearer active only with `--auth-token`; constant-time compare (`MessageDigest.isEqual`, `ConfigdServer.java:725`); loud warning when off. A bearer match authenticates **as `root`** (empty roles) — so in the default config "authenticated via `--auth-token`" ≡ "is root"; control-plane multi-principal separation comes only from `_acl/` policy or the mTLS cert-DN path. mTLS enforced *when TLS configured*, but TLS is off-by-default → plaintext out-of-box. Pluggable authN SPI designed, **not wired** (v2). |
| Authorization — in-core RBAC (**not** pluggable) | Wired, active | `AclService` (`Permission{READ,LIST,WRITE,WATCH,ADMIN}`): union of matching ancestor grants, **absolute deny-precedence**, default-deny; `WATCH` floored by `READ`; role-aware; config-sourced `ConfigPolicy`/`PolicySerializer` under `_acl/`. Default = single `root→ALL`; empty `_acl/` ⇒ byte-identical. |
| Watch-authz (N=1) | Wired, active | `AclServiceWatchAuthorizer`: whole-target `READ ∧ WATCH` cover, **reject-not-filter**, fail-closed on any `Throwable`; `FULL`/`full_chain_verify` → root-only. Bounded revocation under live `_acl/` reload (W7-7). |
| Reserved-prefix ADMIN gate | Wired, active | `_acl/` and `_system/` require `ADMIN` for **all** methods at the HTTP boundary (mutation + disclosure); fail-closed; write-time `_acl/` validation → 400 pre-commit. |
| Rate limiting | **Unconditionally ON** | Global 10k/s + per-principal; gates **before** Raft propose. The one control not off-by-default. |
| Signing-key co-location (D-1) | Fail-closed by default | `enforceSigningKeyNotColocated` throws `SecurityException`; refuses to boot with the key co-located in `dataDir`. HKDF crypto-review flagged pending (S7). |
| At-rest **integrity** (ADR-0042) | Wired, active | HMAC-SHA-256 keyed / CRC32C, constant-time MAC compare, fail-closed. **Tamper-detection, NOT confidentiality.** |
| Encryption at rest | **ABSENT → v2** | No `javax.crypto.Cipher`/AES in `src/main` (verified). Config values incl. `secure/` keys are plaintext `byte[]`. Decided accept-as-v2 (RR-098 OPEN). |

**The deployer MUST-KNOW list (read this before going live):**
1. **Secure-by-config — turn the controls on.** v1 defaults to plaintext + no auth + no audit + no replay
   protection. Before production you MUST set `--auth-token`, configure TLS (→ mTLS enforced on edge/peer),
   enable the audit log, and enable replay protection. Each is off-by-default with a loud warning.
2. **Segregate legacy-SUBSCRIBE from watch clients (the single most important watch condition).** The
   `--edge-port` also serves the pre-existing whole-store SUBSCRIBE fan-out, which has **no per-key ACL**
   (the trusted server↔edge backbone, ADR-0038). A cert that completes the mTLS handshake can pull the
   **whole store** via SUBSCRIBE, bypassing the watch gate. The watch ACL only constrains clients that
   **cannot** reach SUBSCRIBE — deploy watch clients **segregated** from edge-cache subscribers. Not
   reachable in the default config (only `root` can watch, and `root` already holds the whole store), but
   load-bearing the moment a non-root watch is granted on a shared port.
3. **mTLS + explicit grant for any watch.** A watch needs a verified cert-DN **and** an explicit
   `READ ∧ WATCH` grant; plaintext ⇒ all watches rejected (fail-closed). Out-of-the-box only `root` watches.
4. **Encryption is integrity-only — do NOT store secrets.** At-rest gives tamper-detection, not
   confidentiality. `secure/` buys read **freshness**, not secrecy. Keep passwords/tokens/keys/PII in a
   dedicated secret manager. **If your deployment must store sensitive data or meet a compliance bar,
   encryption-at-rest is a v1 blocker for you — raise RR-098 before deploying.**
5. **`scope` is not an authorization boundary at N=1.** Gate/store/read/filter are uniformly scope-blind;
   `scope` is forward-compat metadata. Do not rely on it for tenant isolation in v1.
6. **Reserved prefixes are ADMIN.** `_acl/` and `_system/` require ADMIN for every method (HTTP boundary;
   no non-root principal can observe reserved keys via any watch kind — the full-scope grant is root-only).

**Dormant defect, accounted for honestly.** `SigningKeyStore.java:170` (`writeForTest`) computes
`PosixFilePermissions.fromString("rw-------")` but discards it — the `Files.setPosixFilePermissions` call is
missing, so this helper never chmods 0600. This is a **test-only helper with zero production exposure**:
production `generateAndWrite` (`:142-144`) correctly applies `OWNER_READ|OWNER_WRITE`. Tracked as a trivial
cleanup; **not a v1 blocker.**

**Security residuals (v2 / tracked follow-up, none a stop-ship on the documented posture):** encryption-at-
rest build (node-local AES-GCM at the ADR-0042 seam) + KMS-provider SPI (v2, RR-098); auth-SPI wiring (v2;
authZ stays in-core by design); hardening — gate the legacy SUBSCRIBE path / segregate trust anchors, and
move the reserved-prefix rule into `AclService`; gate-7 residuals (F-S7-TLS-1 leaf-anchor expiry,
active-replay [the guard is passive-only + opt-in], WAL tail-truncation); CVE + gitleaks are **nightly-only**
(not per-merge); HKDF crypto-review pending.

**Verdict (feeds the go/no-go).** The v1 security posture is **shippable with the documented deployer
requirements**: the mechanisms are real, wired, and fail-closed where it matters, and the off-by-default
choice is defensible **as long as the MUST-KNOW list is enforced operationally**. The one qualifier is
encryption-at-rest — a blocker for any deployment that must store sensitive data or meet a compliance bar;
for all others a documented v2 gap with the "do not store secrets" mitigation.

## 6. The v1 ship line & go/no-go recommendation

### 6.1 What v1 IS (proven)
A **region-local, strongly-consistent, sharded, mTLS-securable configuration control plane** — "a single
Raft root for linearizable writes with asynchronous bounded-staleness fan-out to in-process edge readers
(Quicksilver-shaped)":
- **Durable writes** — fsync-before-ack, no early-ack (ADR-0033); PROVEN **0 committed-write loss** under 3
  fault modes on metal.
- **Fast, clean failover** — PROVEN **~372 ms** leader-loss gap, single bounded election; RTO 4.2 s/5.9 s.
- **Horizontally scalable** — PROVEN near-linear **~2.45× on 3 machines** (per-group-independent,
  leadership-managed), cluster-bound by consensus churn not hardware; the scaling path toward the 10 k/s
  aggregate target is **evidenced, not just modeled**.
- **Long-run stable** — PROVEN **6 h** soak leak/OOM-clean.
- **Sharding server-wired + exercised on metal** — `StaticShardMap` + `addGroup` loop + `shardFor` routing +
  0x02 coalesced-heartbeat frame on main; N>1 measured with the real jar (v1 defaults N=1; N>1+edge
  fail-closes unless opted in).
- **N=1 client-facing change-subscription** — RFC §2 watch protocol server-side (whole-target authz, bounded
  revocation).
- **In-core RBAC** — scope/paths/capabilities/roles/policy-as-config/`_acl/`-ADMIN-enforcement.
- **A complete, stand-alone-implementable protocol RFC** (§0–§7).
- A **verified correctness core** — Raft (ReadIndex linearizable reads, pre-vote, joint consensus), 3 TLA+
  specs, Porcupine linearizability, jcstress, mutation-tested (73%), property-fuzzed.

### 6.2 What v1 is NOT (deliberate v2 scope)
The §5.2 list: client drivers, encryption-at-rest build + KMS SPI, auth-SPI wiring, multi-shard watches (v3),
dynamic resharding, `list` endpoint, segment-aware ACL, BATCH API, cross-region/WAN, sub-second region
failover, the leadership balancer, polyglot bindings, the alloc-win merge. **Stated scope, not gaps.**

### 6.3 The measured envelope vs the 10 k/s positioning
- Single-group write knee ≈ **800 w/s** (churn-bound). Edge read: p50 50 ns / **53,616 req/s @64 conn**.
- Horizontal aggregate: **~+475–535 w/s per added leader-machine** (cross-machine), near-linear, proven to
  **1607 w/s @3 machines**. The original 10 k/s baseline is a **sharded-aggregate** target — now evidenced as
  a real path (~17–19 machines at the cross-machine per-group knee, fewer with bigger instances / group-commit
  tuning), **contingent on the leadership-balancing operability work** to sustain 1-leader-per-box at scale.

### 6.4 The recommendation: **GO-WITH-CONDITIONS**
**Reasoning.** The correctness core is verified; the hard empirical claims (durability, stability,
horizontal scale) are now MEASURED green; the sharding server wiring is on main **and exercised on metal**;
the ADRs the contract rests on are ratified; encryption is a decided v2. **No absolute blocker survives.**
The conditions (§0: C1–C4) are a small, named set — three are "publish/enforce the documented deployment
requirements" (the secure-by-config posture is load-bearing enough that folding it into an unqualified GO

secure-by-config posture + leadership-balancing gap are real and must ship as named conditions), and it is
