# RR-096 — FanOutBuffer.readSince torn read under eviction (publish-order hole in the RR-066 fix)
# Pre-fix failure captures + post-fix green. Session 3, 2026-06-11.
#
# THE BUG
# -------
# FanOutBuffer.publish() (the single-writer append path of the ADR-0034
# CommitNotificationSource boundary) used the evicting publish order:
#
#     ring.set(slot, n)   ->   head = head + 1   ->   tail = head - capacity
#
# readSince()'s verify-after-read (read tail t1 -> head h -> copy [t1,h) ->
# re-read tail t2; GAP unless t2 == t1) assumed that a reader observing an
# in-place overwrite would also observe the tail advance. The JMM only
# guarantees the CONVERSE for that store order: the overwrite (ring.set) is
# ordered BEFORE the tail advance, so a reader can
#   1. read t1 = T,
#   2. mid-copy, read a slot the writer has just overwritten (a lapped, NEWER
#      notification at an OLD position),
#   3. finish the copy and read t2 = T (the writer's tail store has not yet
#      executed),
# and pass t2 == t1 — returning a non-GAP run containing a duplicate /
# non-ascending seq. Exactly-once over effect is broken at the boundary the
# Session-3 data plane consumes.
#

# THE FIX
# -------
# Evict-before-overwrite. On eviction the writer now publishes, in order:
#   lastEvictedSeq.set(evictedSeq)  ->  tail = tail + 1  ->  ring.set(slot, n)
#   ->  head = head + 1
# The tail advance precedes the in-place overwrite in the volatile total
# order, so a reader that observed an overwritten slot value (R_slot sees
# W_ring) necessarily observes the tail advance at its re-read (W_tail
# precedes W_ring in sync order; R_t2 follows R_slot in program order) ->
# t2 > t1 -> GAP. Every non-GAP run is again provably clean.
# Transient `head > tail + capacity` exposure is gone (head never outruns
# tail + capacity); the h - t1 > capacity reader check is retained for stale-t1
# windows. Append path stays allocation-free; no locks added.
#
