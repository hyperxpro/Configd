RR-004 (P0) — ack != commit — DISCRIMINATING PRE-FIX FAILURE CAPTURE
================================================================================

Finding : RR-004 / CF-44 / old R-14 — HTTP 200 ("acknowledged") is returned on
          leader-LOCAL append, pre-quorum. An acknowledged write can vanish on
          leader failover (contract §6 CONTRADICTED; observed live in
          docs/audit-session-1/smoke-test.md §3).

Pre-fix  : The propose seam (RaftNode.propose) returns ProposalResult.ACCEPTED the
defect     instant the leader appends the entry to its LOCAL log
           (RaftNode.java propose(), pre-quorum). ConfigWriteService maps that to
           WriteResult.Accepted(proposalId) -> HttpApiServer 200. The "ack" is
           therefore decoupled from quorum commit.

Test     : configd-testkit/src/test/java/io/configd/testkit/AckEqualsCommitTest.java
           Drives the deterministic post-RR-010 simulator with RANDOMIZED
           leader-kill points placed in the window BETWEEN local append and quorum
           commit (killAfterTicks = 1..4, derived from the seed), across SEEDS=200
           seeds, for all THREE fault shapes:
             - LEADER_CRASH                 (leader stops executing + isolated; kill -9)
             - LEADER_ISOLATION             (leader keeps ticking, partitioned from quorum)
             - SLOW_FOLLOWER_QUORUM_DELAY   (a quorum of followers starved before propose)
           The "ack" is observed at the SAME boundary the HTTP path uses — the
           propose seam (ProposalResult.ACCEPTED, equivalently the post-fix
           ProposeOutcome.accepted()) — NOT internal raft commit state.
           Invariant asserted: every write acknowledged as successful is present in
           the post-failover committed log (survives on the new leader of the
           surviving quorum). committedBeforeKill=false in the printed violations
           CONFIRMS the kill lands in the append->commit window (the write was acked
           at local append but was NOT yet committed when the leader was removed).

Tree     : pre-fix HEAD = c452aa19477f50d67b1323702880c283d13a2189
           ("S2/RR-010: thread the master seed into the per-node election RNG ...")
           — i.e. RR-010 determinism fix present, RR-004 ack=commit fix NOT yet applied.

APPENDIX A — POST-FIX PROOF
================================================================================

After the ADR-0033 fix, AckEqualsCommitTest observes the ack at the live commit
seam (RaftNode.whenCommitOutcome — the same seam ConfigWriteService blocks on),
so a write is "acknowledged" ONLY on COMMITTED. The discriminating sweep is GREEN
and NON-VACUOUS (the non-vacuity guard requires ackedAndSurvived > 0):

  ./mvnw -pl configd-testkit test -Dtest=AckEqualsCommitTest \
         -Dsurefire.failIfNoSpecifiedTests=false
  => Tests run: 3, Failures: 0, Errors: 0  (200 seeds x 3 fault shapes)
     - leader crash, leader network isolation, slow-follower quorum delay
     - a write killed in the append->commit window resolves LOST/INDETERMINATE
       (correctly NOT acknowledged => 503/504, not a false 200); every write that
       IS acknowledged (COMMITTED) is present in the post-failover committed log.

Seam-level proof (configd-consensus-core/.../CommitOutcomeSeamTest):
  ./mvnw -pl configd-consensus-core test -Dtest=CommitOutcomeSeamTest
  => Tests run: 5, Failures: 0  (COMMITTED carries per-index seq; different-term
     applied at index => LOST; one-shot fires once; multi-entry batch each carries
     its own seq; no-op => COMMITTED with current seq)

Service-seam proof (configd-server/.../RaftProposerCommitConfirmTest):
  ./mvnw -pl configd-server test -Dtest=RaftProposerCommitConfirmTest
  => Tests run: 4, Failures: 0  (single-node => Committed(seq); follower =>
     NotLeader; outcome-unknown-within-deadline => Indeterminate; APPENDED-but-
     UNCOMMITTED => Indeterminate, NOT Committed)

Affected module suites GREEN (JDK 25, 2-vCPU):
  configd-consensus-core 163 | configd-config-store 240 | configd-control-plane-api 119
  configd-replication-engine 53 | configd-server 80 | configd-testkit 1137
  (testkit run with -Dconfigd.seedSweep.count=500)

Error distinguishability (charter §3): an uncommitted write is reported as
something OTHER than success and OTHER than permanent failure — typed variants
Committed / Lost / Indeterminate / NotLeader / Overloaded (ConfigWriteServiceTest),
mapped to HTTP 200 / 503 / 504 / 503 / 429 respectively.

APPENDIX B — MUTATION CHECK (revert key line -> failing test)
================================================================================

Each key fix line was reverted one at a time; the paired test fails, proving the
test kills the mutant. (Equivalent-mutant note: a naive seq mutation was found to
be behaviorally equivalent because currentAppliedSequence() tracks the per-entry
seq; the seq test was strengthened with a SEQ_OFFSET that decorrelates seq from
the log index so the mutation became observable.)

1) TERM-MATCH PREDICATE  (RaftNode.decideCommitOutcome)
   revert: `if (entry.term() == term)` -> `if (true)`
   => CommitOutcomeSeamTest.differentTermAppliedAtIndexIsLostNotCommitted FAILS
      "a different term applied at the index must be LOST, not COMMITTED
       ==> expected: <LOST> but was: <COMMITTED>"

2) 200-ONLY-ON-COMMIT BRANCH  (ConfigdServer.raftProposer)
   revert: register whenCommitOutcome -> `f.complete(Committed(index))` on accept
   => RaftProposerCommitConfirmTest.appendedButUncommittedIsNotAckedAsCommitted FAILS
      "an APPENDED-but-UNCOMMITTED write must not be acked as Committed
       ==> expected: <...Indeterminate> but was: <...Committed>"

3) SEQ THREADING  (RaftNode.applyCommitted)
   revert: thread apply()'s returned seq -> ignore it, record currentAppliedSequence()
   => CommitOutcomeSeamTest.committedCarriesTheAppliedMutationSeqForThisIndex FAILS
      "first write's COMMITTED seq must be its own applied-mutation seq
       ==> expected: <1001> but was: <1>"
